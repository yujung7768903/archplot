言葉で説明するだけで、クラウド公式アイコン入りのアーキテクチャ図を描く Claude Code スキルです。
draw.io でそのまま開いて編集できる `.drawio` ファイルと PNG 画像が得られます。

## 特徴

- **公式アイコン** — AWS・GCP・Azure・Kubernetes など 17 系統、2,440 個のアイコン
- **境界ボックス** — アカウント・リージョン・VPC・サブネットを入れ子にできます
- **すっきりした線** — 図形と文字を避けて直角に接続します
- **アプリ不要** — draw.io デスクトップアプリなしで PNG を出力します

## インストール

```bash
npx skills add yujung7768903/archplot
```

Python 3、`pip install diagrams`、Chromium が必要です。

## 使い方

描きたい構成を Claude Code に言葉で説明します。

> 注文 API が SQS に注文を入れ、Lambda が取り出して領収書を S3 にアップロードする構成図を描いて

## 線の接続ルール

線は以下のルールに従って図形をつなぎます。

| ルール | 理由 |
| --- | --- |
| 水平・垂直にだけ曲げる | 曲線や斜線は流れが読みにくい |
| まっすぐ行けるなら曲げない | 曲がりは情報ではない |
| 図形を横切らない | 線の終点が分かりにくくなる |
| 文字の上を通らない | 名前が隠れる |
| アイコンの角から線を出さない | 線がアイコンから浮いて見える |
| 入ってくる線同士で接続点を重ねない | 重なった線は 1 本に見える |
| きれいな経路がなければ配置を直す | 斜線で無理につながない |

## 作図ルール

AWS のリファレンスアーキテクチャ図から取ったルールです。

- リソース 1 つにノード 1 つ
- アイコンがあるものだけをノードにする — 関数名・URL・フィールド名は描かない
- 線のラベルは 1〜3 語
- ユーザーはすべての境界ボックスの外に置く
- 正常な流れを 1 本だけ描く — エラー・リトライ・番号は入れない

## 作図ツールの選び分け

| 要望 | ツール |
| --- | --- |
| クラウド公式アイコン、アカウント・リージョン・VPC の境界 | この skill |
| 文書本文に埋め込むフロー図・シーケンス図・状態図 | Mermaid ベースの skill —— Confluence と GitHub がそのまま描画します |
| ピクセル単位の制御 | draw.io アプリを開いて手で描きます |
